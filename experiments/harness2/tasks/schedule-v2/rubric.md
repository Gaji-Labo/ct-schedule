# 採点基準（CT組み合わせ表の作り直し）

要件ファイル `screens/schedule.md`、`docs/design/` のルール、reproduce-02 で人（デザイナー）が指摘したことから、デザイナーの意図を項目にした。各項目は pass / fail。見た目の項目はスクリーンショットで判定する。

1. 画面の Story が `src/design-system/drafts/` にあり、`title` が `Drafts/CTスケジュール/CT組み合わせ表`。`Default` はログイン中・参加者20人
2. 骨組みが `PageLayout` > `PageHeader` > `PageSection`。`<main>` の余白・最大幅を画面で書いていない
3. 1280px の最初の画面（上から 800px）で、今週の自分の相手（またはお休み）が、他のペアより先に・目立つ形でわかる。かつ、週ごとの組み合わせも最初の画面に入り、先の週があることがわかる（カードの見切れ、送りボタンなど）
4. 週ごとの組み合わせは、既存の `CTScheduleCarousel` / `CTScheduleCard` を使うか、それらを拡張して使っている（Story の中に独自の週カードを組んでいない）
5. 前の週・次の週の送りボタンは、`Carousel` の部品（`CarouselPrevious` / `CarouselNext`）をカード列に重ねる形で、PC でも押しやすい。カード列の上に文言つきの outline ボタンを別に並べていない
6. ペアの行は、通常のペア・自分のペア・お休み・ハドルのボタンがある行とない行のどれでも、アバターと名前の位置がそろっている。自分の行に「あなた」などのラベルを足して列がずれていない
7. 同じことを二重に示していない。特に「今週」「予定」を、太枠・Badge・見出し下の説明文など複数の要素で重ねて示していない。要件の1項目に要素を1つずつ足しただけの画面になっていない
8. 祝日の週は組み合わせの代わりに「CT なし」と祝日名で、通常の週とひと目で区別できる（`status-holiday` / `status-rest` のトークンか、それを使う Badge の variant）。`className` で Badge の色を上書きしていない
9. 「CTの参加者：○人」と「メンバー一覧を見る」がある。人数の数字そのものはリンクにしていない
10. 状態の Story がそろっている: 未ログイン（Slack でログインのボタン、ログインすると何ができるかの案内）、参加者が奇数（お休み）、祝日の週、自分がお休みの週、参加者が2人未満（「参加者が2人以上になると組み合わせが表示されます」）
11. 375px と 1280px で横にはみ出していない。lint の design-system/* に違反が無い
12. ページ直下に置いた `Alert` などで見出しの順番が飛んでいない（h1 の次に h5 が来る、など）
