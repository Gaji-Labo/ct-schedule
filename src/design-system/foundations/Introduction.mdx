# Gaji-Labo 社内アプリ デザインシステム

Gaji-Labo の社内アプリの UI を組み立てるための部品とルールをまとめたカタログです。
最初の利用例は CT スケジュールで、Apps にはその部品と画面を載せています。
人と AI のどちらが新しい画面を実装する場合も、ここにあるトークンとコンポーネントだけで組み立てることを目指します。

## 構成

| サイドバー | 置き場所 | 内容 |
| --- | --- | --- |
| Foundations | `src/app/globals.css` / `tailwind.config.ts` / `src/design-system/tokens.ts` / `src/lib/fonts.ts` | 色・タイポグラフィ（フォント・行間）・レイアウト（骨組み・ブレイクポイント・余白・角丸）・階層表現 |
| UI | `src/app/components/ui/` | shadcn/ui ベースの汎用コンポーネント |
| Domain | `src/app/components/` | CTスケジュール固有のコンポーネント (予定) |
| Patterns | `src/app/components/PageLayout.tsx` | ページの骨組み (`PageLayout` / `PageHeader` / `PageSection`) |

違反の一部は `bun run lint` の `design-system/*` ルールで検出されます。

1. **色は Semantic トークンだけを使う。** `bg-gray-100` や `#e5e5e5` を直接書かない。
   該当するトークンが無ければ、トークンを追加してから使う。
2. **既存コンポーネントを優先する。** `<button className="...">` を自作せず、`Button` の `variant` / `size` から選ぶ。
3. **見た目の調整は variant で行う。** `className` での上書きは余白やレイアウトの調整にとどめる。
4. **ライト・ダーク両方で確認する。** ツールバーのテーマ切替で表示を確かめる。

## トークンの2層構造

- **Primitive**: `--neutral-100` などの生の色値。Semantic トークンを定義するときにだけ使う
- **Semantic**: `--primary` や `--feedback-info-subtle` など、用途に名前を付けたトークン。コンポーネントからはこちらだけを使う

ブランドカラーを決めるときは、Primitive を追加して Semantic の参照先を差し替えれば、コンポーネント側は変更せずに済みます。
