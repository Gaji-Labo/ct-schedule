# Gaji-Labo 社内アプリ デザインシステム

Gaji-Labo の社内アプリの UI を組み立てるための部品とルールをまとめたカタログです。
最初の利用例は CT スケジュールで、Apps にはその部品と画面を載せています。
人と AI のどちらが新しい画面を実装する場合も、ここにあるトークンとコンポーネントだけで組み立てることを目指します。

## 構成

| サイドバー | 置き場所 | 内容 |
| --- | --- | --- |
| Foundations | `src/design-system/foundations/`（値は `src/app/globals.css` / `tailwind.config.ts` / `src/lib/fonts.ts`、用途は `src/design-system/tokens.ts`） | 色・タイポグラフィ（フォント・行間）・レイアウト（骨組み・ブレイクポイント・余白・角丸）・階層表現・ロゴ |
| UI | `src/app/components/ui/*.stories.tsx`、`src/app/components/SiteHeader.stories.tsx` | どのアプリでも使う汎用コンポーネント（shadcn/ui ベースと、社内アプリ共通のヘッダー）。各部品の「ガイドライン」ページ（`src/design-system/guidelines/`）もここに出る |
| Patterns | `src/app/components/PageLayout.stories.tsx` | どのアプリでも使うページの骨組み（`PageLayout` / `PageHeader` / `PageSection`） |
| Apps / &lt;アプリ名&gt; / Components | `src/app/components/*.stories.tsx`（`SiteHeader`・`PageLayout` 以外） | そのアプリ専用のコンポーネント（CT スケジュールの週カード、メンバー一覧の行など） |
| Apps / &lt;アプリ名&gt; / Pages | `src/design-system/pages/` | 画面全体をモックデータで再現したもの。部品の組み合わせ方の見本（人が確定させた正式な画面） |
| Drafts / &lt;アプリ名&gt; | `src/design-system/drafts/` | 確認待ちの画面。AI や人が作った画面はまずここに置き、確認して確定したら Apps / &lt;アプリ名&gt; / Pages に移す。`main` には残さない |

## 基本ルール

ルールの正本はリポジトリの <a href={repoUrl("docs/design")}><code>docs/design/</code></a> です。ここでは要点だけを載せます。

| 知りたいこと | ファイル |
| --- | --- |
| 色・余白・文字・使う部品・禁止事項 | <a href={repoUrl("docs/design/rules.md")}>rules.md</a> |
| 画面の目的・見せ方の判断材料（社内アプリ共通の文脈と原則） | <a href={repoUrl("docs/design/principles.md")}>principles.md</a> |
| アプリ固有の目的・画面・利用シーン（CT スケジュール） | <a href={repoUrl("docs/design/apps/ct-schedule.md")}>apps/ct-schedule.md</a> |
| 実装の手順・検証 | Skill <a href={repoUrl(".claude/skills/implement-ui/SKILL.md")}>implement-ui</a>（Claude Code では `/implement-ui`） |
| 仕組みの全体像・フィードバックの戻し先 | <a href={repoUrl("docs/design/workflow.md")}>workflow.md</a> |

違反の一部は `bun run lint` の `design-system/*` ルールで検出されます。

1. **色は Semantic トークンだけを使う。** `bg-gray-100` や `#e5e5e5` を直接書かない。
   該当するトークンが無ければ、トークンを追加してから使う。
2. **既存コンポーネントを優先する。** `<button className="...">` を自作せず、`Button` の `variant` / `size` から選ぶ。
3. **見た目の調整は variant で行う。** `className` での上書きは余白やレイアウトの調整にとどめる。
4. **ライト・ダーク両方で確認する。** ツールバーのテーマ切替で表示を確かめる。

## トークンの2層構造

- **Primitive**: `--neutral-100` などの生の色値。Semantic トークンを定義するときにだけ使う
- **Semantic**: `--primary` や `--feedback-info-subtle` など、用途に名前を付けたトークン。コンポーネントからはこちらだけを使う

ブランドカラーを決めるときは、Primitive を追加して Semantic の参照先を差し替えれば、コンポーネント側は変更せずに済みます。
