# アプリの文脈: CT スケジュール

CT スケジュール固有の目的・画面・利用シーン・原則。社内アプリ共通の文脈と原則は [../principles.md](../principles.md) にある。アプリの実装（データ・認証・ペアリング）は [../../apps/ct-schedule.md](../../apps/ct-schedule.md) にある。

- Storybook での名前: `CTスケジュール`（部品は `Apps/CTスケジュール/Components/`、画面は `Apps/CTスケジュール/Pages/`、確認待ちの画面は `Drafts/CTスケジュール/`）

## 何のアプリか

チーム内で2人1組の CT（コミュニケーションタイム）を毎週組み合わせ、一覧で見せるアプリ。

- CT は毎週月曜に実施する。組み合わせはラウンドロビンで自動生成され、毎週相手が変わる
- 参加人数が奇数の週は、1人が「お休み」になる
- 祝日の週は、カードに祝日名を表示する
- Slack でログインし、相手との Slack ハドルをワンクリックで始められる

## 用語

画面の文言・コード・Story で、次の2つを使い分ける。同じものを別の名前で呼ばない。

| 用語 | 意味 | 例 |
| --- | --- | --- |
| **メンバー** | Slack 連携で登録された社員全員（CT に参加していない人も含む） | 「メンバー一覧」 |
| **参加者** | メンバーのうち、CT に参加している人（`participate` が true） | 「CTの参加者：20人」、メンバー一覧の「参加（20人）」 |

- 人数を出すときは、何の人数かを文言で書く（「現在のメンバー：20人」のように、メンバーと書いて参加者の数を出さない）
- 人数の数字をそのままリンクにしない。リンク先の一覧と数が一致しないと誤解を招くため、遷移は「メンバー一覧を見る」のように行き先を書いたリンクにする

## 主な画面

| 画面 | パス | 目的 |
| --- | --- | --- |
| CT組み合わせ表 | `/` | 今週以降の組み合わせを週ごとのカードで横に並べて見せる。参加者の人数と、メンバー一覧へのリンクを置く（[要件](./ct-schedule/screens/schedule.md)） |
| メンバー一覧 | `/member` | メンバー（社員全員）を「参加」「不参加」に分けて見せる、削除する。見出しの「参加（○人）」はトップの参加者数と一致する（[要件](./ct-schedule/screens/member.md)） |
| マイページ | 未決 | 全員分ではなく自分のみに絞ってペアを見る。プロフィールを編集する（[要件](./ct-schedule/screens/my-page.md)） |

- Header内のアイコンから表示されるポップアップの「編集」が「マイページ」に差し替わってページ遷移する

画面ごとの要件（表示と操作、状態で変わること、未決のことなど）は、`ct-schedule/screens/` の要件ファイルにある。

## ユーザーと利用シーン

- チームメンバーが「今週の相手は誰か」を確かめるために、週の初めに開く
- 滞在時間は短い。目的は「相手を知る → ハドルを始める」で終わる
- メンバーは Slack 連携で追加される。アプリ内にメンバーを追加する操作（ダイアログ・フォーム）は無い
- 管理操作（メンバーの削除、初回ログイン時の設定）はたまにしか行わない

## このアプリ固有の原則

- **今週がすぐわかる** — 最初に目に入るのは「今週の組み合わせ」。過去や遠い未来の情報は控えめにする

## このアプリ固有の色

共通の色は [../rules.md](../rules.md)「色」にある。次のトークンは CT スケジュールの用語で名前を付けているが、定義は共通トークンと同じ場所（`globals.css`・`tailwind.config.ts`・`tokens.ts`）にある。

| 用途 | 使うトークン |
| --- | --- |
| 祝日の週のカード背景 | `bg-status-holiday` |
| 「お休み」「祝日名」ラベル | `bg-status-rest text-status-rest-foreground` |
| 今週の強調枠 | `border-highlight-current` |

「お休み」「祝日名」ラベルは `rounded-full` で使う。現状は Badge に対応する variant が無く、`CTScheduleCard` で className を上書きしている（既知の違反）。直すときは Badge に variant を追加してから使う。

## このアプリ固有の部品

共通の部品は [../rules.md](../rules.md)「コンポーネント」にある。Storybook では「Apps/CTスケジュール/Components/」に出る。

| やりたいこと | 使うもの |
| --- | --- |
| CT の週カードを横に送って見せる | `CTScheduleCarousel`（初期表示は「次の週」だけ、進めると「前の週」が出る）。1枚は `CTScheduleCard` |
| メンバー一覧の1行 | `MemberListItem`（アバター・名前・参加状態。右端の操作は `action` で渡す） |
| メンバー一覧の「参加」「不参加」のまとまり | `MemberGroup`（見出しに人数、0人のときの文言、`MemberListItem` を区切り線つきで並べる） |

## Story で用意する状態

Skill `implement-ui` の「用意する状態」に加えて、次を用意する。

- 祝日の週
- 参加人数が奇数（お休みあり）
- 今週のカード

`Default` のデータは本番と同じ件数にする（CT組み合わせ表は20人）。モックデータは `src/design-system/mocks/ct.ts` にある。
